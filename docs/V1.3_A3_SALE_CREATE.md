## Objetivo
Implementar la primera venta online completa:

Android/PWA -> Cloudflare Worker -> D1

mediante un único comando de negocio:

sale.create

## Principio
Una venta debe ser una sola transacción financiera coherente.

Venta + líneas + inventario + caja:
TODO o NADA.

Nunca debe quedar una venta parcial.

## Autenticación
- Reutilizar exactamente A2.
- Solo dispositivo writer activo puede ejecutar sale.create.
- read_only debe ser rechazado.
- revoked debe ser rechazado.
- credencial inválida debe ser rechazada.
- No duplicar ni reemplazar la arquitectura de autenticación A2.

## operation_id e idempotencia
Cada venta debe recibir un operation_id estable.

Reglas:
1. Primera petición válida con operation_id nuevo:
   procesa la venta una sola vez.
2. Repetición del mismo operation_id con el mismo contenido:
   NO vuelve a crear venta,
   NO descuenta inventario otra vez,
   NO mueve caja otra vez,
   devuelve resultado idempotente.
3. Mismo operation_id con contenido diferente:
   rechazar como conflicto,
   sin efectos financieros adicionales.
4. operation_id debe quedar registrado durablemente en D1.

## sale.create
Implementar un endpoint/comando de negocio único.

No crear API CRUD genérica por tabla.

El servidor debe validar como mínimo:
- operation_id
- device autenticado
- productos/líneas válidas
- cantidades > 0
- importes numéricos válidos
- total coherente
- método de pago admitido por el modelo existente
- datos requeridos antes de iniciar efectos financieros

## Transacción
Dentro de D1:
- crear venta
- crear líneas
- registrar movimientos de inventario
- registrar movimiento de caja cuando corresponda

Todo debe ejecutarse atómicamente.

Si cualquier paso falla:
- rollback completo
- cero efectos parciales

## Inventario
La venta debe producir movimientos auditables.
No implementar rediseño general de inventario.
No modificar reglas comerciales fuera de lo necesario para registrar la venta.

## Caja
Registrar el efecto financiero correspondiente según los datos de la venta.
No rediseñar caja.
No introducir reglas comerciales nuevas.

## Respuesta
Respuesta mínima estructurada:
- status
- operation_id
- sale_id si fue creada
- idempotent/already_processed cuando corresponda
- error code seguro cuando corresponda

No exponer:
- credentials
- credential hashes
- DEVICE_AUTH_PEPPER
- secretos
- SQL interno
- stack traces sensibles
